Manifesto

Stop writing rule JSON by hand

Yealico is a wonderful reader. Hundreds of thousands of people use it to read and watch the open web their own way. But almost everything inside it depends on a tiny group of people: the ones who know how to write a site rule.

And writing a site rule by hand is… a craft. A painful one.

The old way

To create a Yealico rule today, you open the site's HTML and start hunting. You pick CSS selectors for the list items. You write a regex to extract the video URL from the page body — and pray the replacement string is exactly right. You compare page 1 and page 2 to reverse-engineer the pagination format. You repeat everything for the detail page, the gallery, the search page, the tags. One misplaced key, one field built from memory instead of from a proven shape, and the app crashes on import.

Most users never even try. They wait for someone else to publish a rule — and if nobody does, that site simply doesn't exist for them.

The shift

iYegen exists to flip that equation. Instead of you adapting to the JSON, the app goes to the site:

  • It loads the page in a real, JavaScript-capable browser — the same way Yealico will see it.
  • It measures the page: where the items are, where the video hides, how pagination changes from page to page.
  • It asks you the one question that matters — "is the video on this page?" — and follows your answer down the chain.
  • It hands you a complete, ready-to-import rule JSON.

The point: every Yealico user already knows which sites they want. The only thing missing was a tool that speaks JSON fluently so they don't have to.

Consumers become creators

When creating a rule takes one minute instead of one evening, the ecosystem changes. More people create rules. More rules get shared. More sites work in the reader — for everyone. iYegen doesn't compete with Yealico or any other reader: it is the factory that feeds them.

Stop writing rule JSON by hand. Paste the URL. Tap the wand. Create.
